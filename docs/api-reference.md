## GSLive Manager (Partner 118): operator deep links

GSLive is a third-party operator console, **not** a server of this API. The links below are
deep links an operator opens in a browser; they carry no request contract of ours. Every
per-account link is produced by `lib/gslive_manager_deeplink_sidecar.ts` and can be generated
with `./bin/dx gslive <LOGIN>`.

| Surface                           | Route                  | What it answers                                                                        |
| :-------------------------------- | :--------------------- | :------------------------------------------------------------------------------------- |
| Account report (batch)            | `#/reports/users`      | Profit, bets, hold %, wager and leg counts for one `player_<LOGIN>` over a day window. |
| Live settling stream (`calcTime`) | `#/events/bet-history` | Tickets as they settle/populate for the current desk day.                              |
| Live placement stream (`betTime`) | `#/events/bet-history` | Tickets as they are placed.                                                            |

### Account report rules

- `bot=true` is mandatory. The SPA defaults the bot switch off, which hides syndicate accounts such as `player_CHURN_003` and `player_NOISE_BOT_77`.
- `from` and `to` must be explicit ISO-8601 UTC desk-day boundaries (`00:00:00` to `23:59:59` in `America/Chicago`). A bare `text=` search renders an empty grid.
- `searchBy=player` and `text=player_<LOGIN>`; `partnerId=118`.

Example (fixed churn window; the CLI emits today's rolling window):

```text
https://plive.sportswidgets.pro/manager-tools/#/reports/users?bot=true&eventId=&from=2026-10-18T05%3A00%3A00.000Z&partnerId=118&searchBy=player&text=player_CHURN_003&to=2026-10-26T04%3A59%3A59.000Z
```

### Live bet-history rules

- `from` and `to` are the desk-day start in **epoch seconds**; `toTime` is the offset to the last second of that day (`86399`, or `89999`/`82799` on US DST transition days).
- `minVolume=0` and `maxTimeUntilScore=0` disable volume/score-time filtering so live tickets appear immediately.
- `t` is an epoch-millisecond cache-buster and must be fresh on every open.
- `dateFilterBy=calcTime` follows settlement; `dateFilterBy=betTime` follows placement.
- `partnerUserId=<LOGIN>` (raw login, e.g. `AF12`) filters to one player; the live console emits the unprefixed form. It is **unverified** as a server-side filter — confirm by row count, and if the grid is not filtered, filter in the console.

```text
https://plive.sportswidgets.pro/manager-tools/#/events/bet-history?minVolume=0&maxTimeUntilScore=0&from=1793422800&to=1793422800&toTime=86399&dateFilterBy=calcTime&t=1793469958152
https://plive.sportswidgets.pro/manager-tools/#/events/bet-history?minVolume=0&maxTimeUntilScore=0&from=1793422800&to=1793422800&toTime=86399&dateFilterBy=betTime&t=1793469958152
```

Per-player variant (adds `partnerUserId`):

```text
https://plive.sportswidgets.pro/manager-tools/#/events/bet-history?minVolume=0&maxTimeUntilScore=0&from=1793422800&to=1793422800&toTime=86399&dateFilterBy=calcTime&t=1793469958152&partnerUserId=CHURN_003
```

## Authentication & sessions

### `fantasy402Cookie`

**Declared type:** apiKey in `cookie` named `session`.

Fantasy402 Manager portal session. [OBSERVED] 2026-11-01: a Manager page sends `Authorization: Bearer &lt;token>`, where the token is `sessionStorage.credentials.code` after login. The same request without that header is refused with 401 by openresty, so the cookie alone is not sufficient. The 2026-10-28 HAR carried no Authorization header, which is now contradicted. The cookie name is unrecorded, so 'session' is a placeholder label.

Observed: the 2026-10-28 Manager HAR session is cookie-based and sent no Authorization header (`operational_guardrails_runbook.md:153`). The 2026-10-31 captures record an `authorization` key with a **redacted** value, so whether the current session also sends a bearer token is **unverified — check this**. No login/`Set-Cookie` exchange was captured, so the cookie name, lifetime, renewal window and scope are **unverified**. Do not assume a JWT lifetime — the earlier “~20–25 minute” claim had no source and was removed.

### `daemonBearer`

**Declared type:** http `bearer`.

Static daemon admin token: Authorization: Bearer &lt;SPORTSDESK_ADMIN_TOKEN>, compared with crypto.timingSafeEqual (sportsdesk_webview_server.ts:27-47). The daemon answers 503 when SPORTSDESK_ADMIN_TOKEN is unset and 401 otherwise.

Implementation-verified: the local daemon compares `Authorization: Bearer <token>` against `SPORTSDESK_ADMIN_TOKEN` in constant time (`sportsdesk_webview_server.ts:27-47`), protects `/api/watchlist` and `/api/telegram/*` (`:176-183`) and returns 503 when the token is not configured.

### Session lifecycle

No login, refresh or logout exchange was captured in this release. The only real wire artifact is the 2026-10-28 Manager HAR request capture, which shows a cookie-based session and no `Authorization` header; its response bodies and `Set-Cookie` were not captured. Treat any token lifetime, refresh window or logout behaviour as a **proposal** until captured (see [docs/evidence/capture-requests.md](./evidence/capture-requests.md)).

> The ledger distinguishes captured wire evidence from observation and inference: five Manager operations (`getWebLog`, `getInfoPlayer`, `getBetTicker`, `getBetTickerConfig`, `getSportsVigSetup`) have live request+response captures from 2026-10-31 and publish capture-derived response schemas; every other response schema is authored unless its row says otherwise. Earlier wire artifacts are the 2026-10-28 Manager HAR (mode-B request only) and the 2026-10-31 live run, whose three remaining requests (`getPending`, `getInfoManager`, `getCustomerNotes`) returned HTTP 500 with the current request template. Sub-sport lanes and period menus are desk-navigation catalog data, not yet captured live; live pregame sports parity is verified separately (19/19 sports, `getSportsType`). GS Buckeye 2 Partner 118 live acquisition is blocked by design — no endpoint, method, authentication mechanism or response contract for any GS report has been verified, and the observed `getBetReport` payload does not establish a transport. The 11 "Tracked Operational Domains" entries are UI/DOM declarations with candidate URLs and methods, not wire contracts, and the `/api/desk/*` routes are documented without any implementation. Treat any schema or behaviour not marked tier B as a proposal to be confirmed by capture, not as a contract.
